# ADR 0001：固定线程与有界 Worker 请求队列

- 状态：已接受
- 版本：V0.1.2

## 背景

文件占用、系统端口表和进程关系查询都可能阻塞。若每次点击都创建线程，或使用无界请求队列，连续刷新会导致线程和待处理任务持续增长；旧查询还可能晚于新查询返回并覆盖当前界面。

## 决策

后台执行器固定创建四个命名工作线程，共享一个容量为 32 的同步请求队列。UI 使用非阻塞 `try_send` 提交任务；队列满或执行器断开时立即返回可展示错误，不阻塞界面线程。

每个请求由单调递增的 `request_id` 标识，请求与事件都携带该标识和目标工具边界。同一工具再次提交后，应用外壳只接受最新 `request_id` 的进度与终态事件；旧终态不会清除新请求的忙碌状态，也不会路由到工具模块。

事件协议同时保留 `Progress` 与 `Finished` 两类事件。V0.1.2 的系统查询主要使用终态，后续耗时工具可以复用进度字段，无需改变 Worker 与 UI 的消息边界。线程创建失败作为启动错误返回，进入现有启动诊断流程。

## 结果

- 固定线程数限制并发 Windows API 调用，容量 32 的队列提供明确背压。
- 重复刷新保持可响应，最终展示同工具最新请求的结果。
- 应用退出时通过通道断开自然结束 Worker，不自动终止其他进程。
- 四线程和容量 32 是当前实现固定值；若未来调整，必须同步负载测试与本 ADR。
