# ADR 0003：持久通信会话线程

## 状态

已接受。

## 背景

现有固定 Worker 池面向文件锁、端口表、进程、DNS、Ping 和 MTR 等有明确终态的任务。TCP、UDP 与串口调试需要在页面切换后继续持有资源并持续收发，如果复用短任务 Worker，会长期占用线程并破坏当前队列的响应边界。

## 决策

应用外壳新增 `CommunicationDispatcher`。每个活动工具至多拥有一个专用会话线程，TCP、UDP 和串口分别以工具类型作为会话键；串口列表枚举仍作为短任务进入原有 Worker 池。

每个会话使用容量 64 的命令队列和容量 64 的事件队列。会话线程把记录按最多 128 条或最长 50 ms 合并为一个事件，避免逐条刷新 UI。单工具日志只保留最近 10,000 条且原始载荷不超过 16 MiB，达到任一上限时淘汰最旧记录；事件队列拥塞导致的丢弃单独统计。

Dispatcher 在每次替换会话时递增 generation。所有事件携带 generation，应用外壳只把当前 generation 的事件交给工具模块，旧线程的迟到记录不能进入新会话。切换页面不会停止会话，应用退出时 Dispatcher 向全部线程发送停止命令并等待其关闭套接字、串口和待写缓存。

TCP 服务端每个连接独立维护不超过 1 MiB 的待写队列并处理部分写入；UDP 保留数据报边界与来源；串口独占打开并使用有界读取超时。连接断开、设备拔出或读写失败都会进入终态，定时发送由工具页面停止，后续重连必须由用户发起。

## 取舍

该设计增加了每个活动通信工具一个长期线程，但避免引入异步运行时，也不改变现有 Worker 数量和 `ToolInvocation`。连接参数、载荷和日志不自动持久化，减少敏感通信数据落盘；需要保存时由用户通过系统保存对话框显式导出 UTF-8 `.log`。
