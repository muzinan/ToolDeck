# ToolDeck v0.3.2

本版本修复 Windows IPv4 Ping 在部分网络环境下可能探测错误目标的问题。现在应用会按 Win32 ICMP API 要求传递 IPv4 地址，关闭代理的 TUN 模式后也不会再因地址字节顺序错误而产生误导性的全丢包结果，同时继续保持 Ping 只反映真实 ICMP 回显的诊断语义。

## 重点更新

### 修复 IPv4 Ping 目标地址转换

- IPv4 Ping 统一使用 Win32 网络字节序转换，确保 ICMP Echo 请求发送到用户输入或域名解析得到的实际目标。
- Ping 与 MTR 现在共用同一套经过纯逻辑用例覆盖的 IPv4 地址转换方式，避免两个工具对同一地址产生不同解释。
- IPv6 Ping 的地址处理保持不变，不影响现有 IPv6 探测行为。

### 保持纯 ICMP 连通性语义

- Ping 不会自动补充 TCP 探测，也不会根据端口开放状态修改 ICMP 接收数、时延或丢包率。
- 目标未返回 ICMP Echo 时仍显示真实的 ICMP 丢包结果，不把其他协议的连通性混入统计。
- 超时提示调整为“ICMP 请求超时或未收到回显”，避免把未收到 ICMP 回显直接表述为整台主机不可达。

## 修复与改进

- 修复 IPv4 地址直接转换为整数后传入 Windows ICMP API，可能导致地址字节顺序反转的问题。
- 将 IPv4 Win32 地址往返测试改为通用命名，明确该转换同时服务于 Ping 和 MTR。
- 未改变 Ping 页面布局、操作方式、参数范围、公开数据结构或命令行调用方式。

## 升级说明

- 支持 Windows 10/11 x64，系统与架构要求不变。
- 不涉及配置迁移、额外授权或网络代理设置，可直接覆盖升级。
- 如果目标主动屏蔽 ICMP，Ping 仍可能显示 100% 丢包；这代表未收到 ICMP 回显，不等同于其他协议一定不可达。
